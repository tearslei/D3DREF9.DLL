# 新构建版启动错误分析与回滚指南

## 现象

客户端显示 `CROSS FIRE ERROR / Do you want to report to ERS system?`，随后退出。该现象发生在将自治构建版放入客户端目录后。

## 已观测事实

- 客户端目录自治 DLL：`84992` bytes。
- 原始备份：`D3DREF9.before-ordinal1.bak`，`1880228` bytes。
- 原始与新构建版不是同一个二进制接口实现：原始 ordinal 1 RVA `0x4A7E` 的入口包含完整初始化调用链；新壳入口仅执行自治线程初始化。
- 进程曾加载 `C:\Windows\System32\D3DREF9.DLL`，说明当客户端目录文件缺失时会回退到系统搜索路径。
- 新构建版内部安装 `crossfire.exe + 0x23567F` relay，并尝试修改代码页；这属于当前崩溃候选点。
- 日志能记录 `event=installed`、`event=device_captured`，但未产生有效实体 CSV。

## 立即恢复客户端

确认 CF 已退出后执行：

```powershell
$client='E:\game\已加速- CF2.0搭建（使用2012系统）\客户端\10.4CrossFire'
Copy-Item -LiteralPath (Join-Path $client 'D3DREF9.before-ordinal1.bak') -Destination (Join-Path $client 'D3DREF9.DLL') -Force
```

恢复后确认客户端目录存在 `D3DREF9.DLL`，再启动原客户端验证。

## 当前工程决策

在确认原始 ordinal 1 的调用约定、返回值和初始化副作用之前，停止把自治 DLL 直接替换到真实客户端目录。后续开发改用隔离副本或独立加载模式：

1. 原始 DLL 保持不动；
2. 只读采样器使用正常启动后的进程；
3. 坐标 relay、D3D9 vtable 仅在测试副本中启用；
4. 每次只启用一条 hook，并记录恢复字节；
5. 只有通过启动、地图、退出三项回归后才合并。

## 分阶段恢复路径

```text
回滚原 DLL
  → 验证原客户端可启动
  → 隔离副本加载自治 DLL
  → 先禁用坐标 relay
  → 验证 D3D9 设备只读捕获
  → 再启用坐标 relay 并检查签名/线程安全
  → 最后进入实体/矩阵 Gate A
```

## 结论

当前错误不是采集数据不足，而是新构建 DLL 与客户端原始加载契约/运行时完整性检查尚未证明兼容。必须先恢复可启动基线，再继续阶段一；不能把错误版本继续用于实际对局。
